## 3. Classification rules

**S — safe to translate.** No runtime effect, or the text is only read by humans. Translation is free-form, but must keep meaning and technical precision.

**C — compatibility-sensitive.** The text is one of the following:
- visible in an API response (`detail`, 413 body, 503 messages raised from the AI or Stellar layer);
- persisted per record (the AI disclaimer);
- fed to the AI model;
- relied on by an assertion.

C items must follow the exact mapping in §5. Every coupled test must be updated **in the same batch**, at **equal strength**: an exact match stays exact, and a substring check stays a distinctive substring.

**M — must remain unchanged.**
- Original legal documents and evidence quotations.
- Stored user data.
- Historical audit records.
- Programmatic identifiers.
- Deliberate test vectors.
- User-owned local files.

### 3.1 Invariants (never changed by this migration)

- **Code and schemas:** business logic, control flow, exception types, status codes, response shapes, headers, field names, enum values, routes, permissions, DB schema/indexes, env var names, dependency versions.
- **Security behaviour:**
  - Identical 404 bodies for "missing" and "out of scope". The equality pairs are listed in §5.1.
  - No internal paths, hashes or secrets in messages.
  - Log **event keys** stay unchanged: `passport.out_of_scope`, `authz.permission_denied`, `authz.out_of_scope`, `storage.*`, `download.*`, `upload.*`, `access_config.*`, `legacy_credentials.ignored`. Tests and monitoring depend on them; only the free-text tail after the key is translated.
- **CLI output format:** `python -m app.access_tool new-token` prints the token and hash on lines starting with two spaces, and label lines must not start with two spaces. Tests parse this, so only the label wording changes.
- **Data and history:** the DB, DB backups, `.env`, `access_control.json`, `secrets/`, git history, commit messages and the backup folder are never touched.
- **Tests:** the test count stays 280 / 34 with identical test IDs. No test is removed, skipped or loosened.

4. **Assertion-strength review** (batches 3–5): every edited assertion keeps its form. Exact stays exact; a substring check stays a distinctive substring; no assertion is removed or loosened.
